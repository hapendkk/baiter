# Baiter

Baiter — учебный проект по разработке приложения с использованием готовых моделей машинного обучения.

Приложение работает с четырьмя типами входных данных: текстом, аудио, изображениями и видео. Для каждого типа данных используется отдельная модель или набор моделей. Результатом работы является текст, который используется для формирования кликбейтных заголовков.

В проекте используются Django для веб-приложения и FastAPI для REST API.

## Задачи проекта

В проекте реализованы четыре задачи машинного обучения:

1. **Текст** — по ключевым словам или текстовому описанию генерируются варианты заголовков.
2. **Аудио** — речь из аудиофайла преобразуется в текст, после чего для полученного текста генерируются заголовки.
3. **Изображение** — модель анализирует изображение и формирует его текстовое описание, которое используется для генерации заголовков.
4. **Видео** — из видео извлекаются отдельные кадры, после чего модель формирует описание происходящего.

Все модели в текущей версии проекта работают с английским языком.

## Используемые технологии

### ML-фреймворки

В проекте используются два фреймворка для работы с моделями машинного обучения:

* **Hugging Face Transformers** — работа с текстовой, визуальной и мультимодальной моделями;
* **PyTorch** — выполнение моделей машинного обучения.

### Остальные технологии

* **Django** — веб-приложение;
* **FastAPI** — REST API;
* **Pydantic** — валидация входных данных API;
* **PyTest** — тестирование API;
* **Moonshine Voice** — распознавание речи;
* **FFmpeg** — обработка аудио и извлечение кадров из видео;
* **Pillow** — обработка изображений.

## Описание моделей

### Текст

Для генерации заголовков используется модель:

`EnglishVoice/t5-base-keywords-to-headline`

На вход подаются ключевые слова или текстовое описание. Модель генерирует несколько вариантов заголовка.

### Аудио

Для распознавания речи используется **Moonshine Voice**.

Аудиофайл преобразуется в текст. Полученный текст затем передаётся в модель генерации заголовков.

### Изображение

Для анализа изображений используется:

`Salesforce/blip-image-captioning-base`

Модель создаёт текстовое описание содержимого изображения. Полученное описание используется для дальнейшей генерации заголовка.

### Видео

Для обработки видео используется:

`llava-hf/llava-onevision-qwen2-0.5b-ov-hf`

Сначала из видео с помощью FFmpeg извлекаются отдельные кадры. После этого модель анализирует кадры и формирует описание происходящего в видео.

## Установка

Клонировать репозиторий:

```bash
git clone https://github.com/hapendkk/ml-project.git
cd ml-project
```

Создать виртуальное окружение:

```bash
python -m venv .venv
```

Активировать его:

```bash
.venv\Scripts\activate
```

Установить зависимости:

```bash
pip install -r requirements.txt
```

Для работы с аудио и видео также требуется установленный **FFmpeg**.

## Запуск Django

Запустить веб-приложение:

```bash
python manage.py runserver
```

После запуска приложение доступно по адресу:

```text
http://127.0.0.1:8000/
```

## Запуск FastAPI

Для запуска API используется:

```bash
uvicorn api.app:app --reload
```

Swagger-документация доступна по адресу:

```text
http://127.0.0.1:8000/docs
```

Основной endpoint для генерации заголовков:

```text
POST /api/generate-headlines
```

Пример запроса:

```json
{
    "keywords": "a mysterious discovery in the ocean"
}
```

Пример структуры ответа:

```json
{
    "keywords": "a mysterious discovery in the ocean",
    "headlines": [
        "Scientists Made a Discovery That Could Change Everything",
        "What Was Found Deep in the Ocean Has Shocked Researchers",
        "Nobody Expected to Find This Underwater",
        "This Ocean Discovery Is Raising New Questions",
        "Researchers Reveal What They Found Beneath the Surface"
    ]
}
```

## Тестирование API

Для запуска тестов:

```bash
python -m pytest api/test_api.py
```

В тестах проверяются:

* доступность главной страницы API;
* успешная генерация заголовков;
* обработка пустого значения `keywords`;
* обработка некорректного тела запроса.

При тестировании функция генерации заголовков заменяется тестовой функцией, поэтому для самих API-тестов не требуется повторно запускать ML-модель.

## GitHub Actions

Для автоматической проверки API используется GitHub Actions.

Workflow запускается при:

* `push` в ветки `main` и `master`;
* создании `pull request` в эти ветки.

Во время выполнения workflow устанавливаются зависимости проекта и запускаются тесты PyTest.

Файл workflow:

```text
.github/workflows/test.yml
```
